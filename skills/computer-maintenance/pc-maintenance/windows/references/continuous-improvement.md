# 持续改进（Continuous Improvement）

## 指标追踪（每台机器只盯四个数）

| 指标 | 采集命令/来源 | 健康线 |
|---|---|---|
| 稳态开机时长 | Diag-Perf 事件 100 | 老旧商务本 ≤45s |
| 启动降级事件数 | Diag-Perf 事件 101（本次开机） | 0 |
| 启动项+第三方服务+非微软任务总数 | health-check.ps1 | 持续下降后稳定 |
| C 盘剩余空间 | Get-Volume | >15% |

每次维护把四个数记入机器档案的"指标基线"，形成趋势。**只比对趋势，不凭单次数值下结论**（单次可能受更新首启影响）。

## 维护周期

| 频率 | 动作 | 耗时 |
|---|---|---|
| 每月 | 完整关机→冷启动一次（验证稳态开机）；Defender 全盘扫描；磁盘清理；核对备份真的跑成功 | ~10 分钟 |
| 每季 | 跑 health-check.ps1 与上季比对；复查 BIOS/驱动更新；复查注册表孤儿项 | ~20 分钟 |
| 每次大更新后 | 四项验证（启动项/服务/任务/注册表）+ 二次清除被回填的项 | ~10 分钟 |
| 症状出现时 | 按 SKILL.md 阶段 1-2 定向采集，先定位根因再动手 | 按需 |

## 复盘协议（每次维护后必做）

1. 这次维护中**什么判断被事实证明错了**？（如：曾把用户的群晖 Clash 当失效代理——实际是活的）→ 写进机器档案"网络特性"或技能陷阱清单
2. **哪个诊断手法最省时间？**（如：双采样法判定安装是否卡死）→ 提炼进 references
3. 用户有没有给出新的偏好/约定？（如"卸载类逐项确认"）→ 写进用户级记忆
4. 沙箱/环境有没有新限制？（如某命令被禁、某域名不通）→ 写进 SKILL.md 避坑清单

## 技能自身迭代规则

- 本技能是**活文档**：每维护一台新机器、每踩一个新坑，回来更新对应 references 或 SKILL.md 避坑清单
- 迭代粒度：新陷阱/新手法的经验≥2 次复现才值得写进 SKILL.md 铁律；单次意外放 references 案例区
- 技能更新后，在机器档案的"整改历史"里记一行"技能版本迭代：<日期> <改了什么>"
- 其他机器部署时：把技能包（package 出的 zip）拷到目标机器的 `~/.workbuddy/skills/`，再按该机情况校准 references 中的命令（不同品牌机器的驱动/管理工具不同）

## 反模式（禁止）

- 不体检就动手"优化"
- 用"感觉慢了"替代事件日志证据
- 批量卸载不逐项确认
- 把密码/key 明文写进记忆或档案
- 功能更新暂存中手动重启
- 单次指标异常就改配置（先复现、再比对趋势）
